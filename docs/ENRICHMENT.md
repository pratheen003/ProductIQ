# ProductIQ AI Enrichment Engine — Technical Reference

## Overview

The ProductIQ AI Enrichment Engine is the Phase 4 intelligence layer of the pipeline. It consumes validated, normalized product data from Phase 2 and Phase 3 and applies grounded LLM reasoning via Groq / OpenAI to produce structured commercial product intelligence.

---

## Module Structure

```
productiq/enrichment/
    __init__.py          — public API exports
    base.py              — BaseEnricher interface
    models.py            — EnrichmentClaim, ProductEnrichment, BatchEnrichmentReport
    prompts.py           — Versioned prompt templates and context builder
    service.py           — MotorEnricher, BatchEnricher orchestrators
```

## Data Models

### 1. `EnrichmentClaim`

Represents an atomic claim generated by the enrichment process:

| Field | Type | Description |
|---|---|---|
| `claim_text` | str | Factual or inferred assertion |
| `category` | str | `performance`, `mechanical`, `electrical`, `application`, `standard` |
| `field` | Optional[str] | Canonical field name (e.g. `rated_power`, `ip_rating`) |
| `is_source_backed` | bool | `True` if directly grounded in source evidence; `False` if inferred |
| `evidence_sources` | List[str] | Provenance source references (e.g. `["pdf:p.5"]`) |
| `confidence` | float | 0.0 to 1.0 confidence score |
| `notes` | Optional[str] | Reasoning notes or basis of inference |

### 2. `ProductEnrichment`

The complete structured enrichment output:

- `product_id`: Unique identifier (e.g. `PIQ-W22SP-4P-1.1`)
- `manufacturer`: Manufacturer name (`WEG`)
- `model`: Motor model name (`W22 Severe Process IE3 (4-pole)`)
- `summary`: High-level commercial synthesis for technical buyers
- `technical_description`: Detailed engineering paragraph
- `key_selling_points`: List of high-impact commercial value propositions
- `target_applications`: Recommended industrial equipment and environments
- `suggested_keywords`: B2B search, procurement, and catalog indexing keywords
- `inferred_fields`: Dict of inferred parameters (e.g. `frequency: 50 Hz`, `poles: 4`)
- `source_backed_claims`: List of `EnrichmentClaim` with `is_source_backed=True`
- `inferred_claims`: List of `EnrichmentClaim` with `is_source_backed=False`
- `unresolved_conflicts`: Explicit list of preserved multi-source disagreements
- `missing_information_notes`: Notes on unverified or omitted attributes
- `enrichment_warnings`: Warnings on conflicted or high-uncertainty parameters
- `metadata`: Provider, model, prompt version, timestamp, total claim counts

## Multi-Provider LLM Abstraction

```python
from productiq.config import Config, load_config
from productiq.llm import LLMClient

# Automatically loads Groq (primary) or OpenAI (fallback) from environment
client = LLMClient()

# Provider-agnostic text call
text = client.call("Explain IE3 efficiency standards.")

# Provider-agnostic structured JSON call
json_data = client.call_json("Return JSON: ...")
```

### Provider Configuration Table

| Environment Variable | Description | Default |
|---|---|---|
| `LLM_PROVIDER` | Active provider (`groq` or `openai`) | `groq` |
| `GROQ_API_KEY` | API key for Groq | Required if provider is `groq` |
| `OPENAI_API_KEY` | API key for OpenAI | Required if provider is `openai` |
| `LLM_MODEL` | Active model identifier | `openai/gpt-oss-20b` (Groq) / `gpt-4o-mini` (OpenAI) |
| `LLM_TIMEOUT_SECONDS` | Request timeout in seconds | `30` |

## Anti-Hallucination Pipeline Flow

```
NormalizedProduct + ProductValidationReport
                     ↓
        build_enrichment_payload()
        - Separate verified facts
        - Extract unmapped specs (torque, inertia)
        - Isolate conflict records
                     ↓
             build_user_prompt()
        - Enforce JSON-only output
        - Enforce claim separation
                     ↓
           LLMClient.call_json()
        - Structured JSON generation
        - Rate limit backoff & retry
                     ↓
       _parse_and_validate_response()
        - Verify all Phase 3 conflicts preserved
        - Tag source_backed vs inferred claims
        - Attach evidence provenance
                     ↓
              ProductEnrichment
```
